# Search and Knowledge-System Patterns

This reference records external implementation patterns worth copying conceptually. It is not a requirement to adopt a specific vendor.

## Algolia DocSearch

Useful patterns:
- indexing and frontend are separate concerns;
- crawler-driven reindexing avoids stale hand-maintained search lists;
- result UI supports breadcrumbs/badges/facets;
- contextual filters constrain search to the relevant document set;
- analytics can reveal failed or common queries.

THC adaptation:
- keep our own canonical search-document schema;
- allow a future Algolia adapter without changing THC-ENC IDs;
- index only publication-authorized public content into any hosted public search provider.

## Docusaurus

Useful patterns:
- content metadata drives navigation;
- autogenerated sidebars/categories reduce manual navigation drift;
- stable explicit slugs protect links through reorganizations;
- sidebars generate previous/next navigation and breadcrumbs;
- tags add a second categorization dimension.

THC adaptation:
- generate topic navigation from the controlled registry;
- use permanent THC-ENC identity independent of title;
- generate previous/next and breadcrumbs from registry order;
- represent tools, symptoms, formats, stage, and topic as searchable metadata.

## Pagefind

Useful patterns:
- index only the meaningful body rather than navigation/chrome;
- page metadata becomes filter facets;
- filters can be loaded independently and show result counts;
- static-site search can remain serverless.

THC adaptation:
- keep structured facets in the generated encyclopedia discovery index;
- if public pages become static enough, Pagefind can be an optional build target.

## MiniSearch / FlexSearch

Useful patterns:
- client-side full-text indexing works well for modest corpora;
- prefix/fuzzy search and field weighting materially improve findability;
- suggestions/autocomplete reduce zero-result searches;
- document fields can be boosted and filtered.

THC adaptation:
- 420+ lessons are small enough for an optimized local index;
- title/ID/terms should outrank long body text;
- symptom, misconception, measurement, and synonym fields need explicit indexing;
- keep provider choice behind one search-document contract.

## Britannica / encyclopedia-style systems

Useful patterns:
- entry identity and revision history matter;
- multimedia is integral to comprehension;
- external references and related topics extend an entry;
- a large encyclopedia needs global search plus browse pathways.

THC adaptation:
- preserve revision/release control;
- treat visuals as lesson requirements, not decoration;
- show sources and evidence limits;
- keep topic browsing alongside search.

## Decision

Current default:
- canonical JSON lesson source;
- generated THC search/discovery document;
- existing local Fuse frontend while the corpus is small;
- provider-independent facets and field weights;
- optional future Pagefind/MiniSearch/Algolia adapter.

Do not rewrite the encyclopedia into Docusaurus/MkDocs merely to copy their UX. Copy the proven architecture patterns while preserving our WordPress/public-route deployment model.
